## Correction to the 2026-11-14 handoff

That handoff says `sampman_oal.cpp` recomputes every stream length at
startup even when the cache loads. It does not: the recompute loop sits in
the `else` branch of `if (cacheFile)` (`reVC/src/audio/sampman_oal.cpp:920-956`),
so an existing cache skips it. No action was needed because the cache was
written while the archives were present and still holds correct lengths,
but a cache written while files are missing would keep zero lengths.

## Radio volume

Vehicle radio is a music stream and follows the **Music Volume** slider;
SFX Volume is a separate control. `SetStreamedVolumeAndPan` scales it as
`(m_nMusicFadeVolume * nVolume * m_nMusicVolume) >> 14` and then by
`/ MAX_VOLUME` in `CStream::SetVolume`:

- `m_nMusicFadeVolume` stays 127; radio `nVolume` tops out at
  `MAX_RADIO_VOLUME` (100); `MAX_VOLUME` is 127.
- Saved `MusicVolume=13` gave a gain of about 8 percent, which is
  barely audible under the engine and full SFX.
- The file was set to `MusicVolume=65` (menu maximum), giving about
  39 percent; SFX at 65 is about 50 percent. Only that line changed;
  the previous file is at `/tmp/reVC.ini.before-radio-volume`.
- Slider changes are persisted through `SaveSettings` ->
  `SaveINISettings` (`LOAD_INI_SETTINGS` is defined at
  `reVC/src/core/config.h:290`), so the menu slider writes this key
  directly. If it reverts, check the save path, not the audio code.

The stock ceiling at maximum Music Volume is about 39 percent of full
scale (`MAX_RADIO_VOLUME` 100 against `MAX_VOLUME` 127). If that is still
too quiet, the next step is a radio-only gain boost in the OAL stream
path, which needs a code change and a build.
